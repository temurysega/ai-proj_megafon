# Навык: варианты и возражения

1. Прочитай `knowledge/methods/options-and-objections.md`, `unit-economics.md`, `pricing-monetization.md`.
2. `options.md` по шаблону `knowledge/templates/options.md`. Заголовки вариантов строго `## Вариант X — …`.
   Обязательно: «Оставить как есть», «Закрыть направление», ≥1 смелый вариант. Варианты различаются логикой ценности.
3. Для каждого: суть; что должно быть правдой (условия со ссылками `[C…]`); экономика (пороги безубыточности
   как `estimate`); **сильные возражения** (от финансов, юристов, маркетинга, пользователя) и ответы; риски и
   обратимость; что проверить первым.
4. Сравнение по критериям из брифа (таблица) и рекомендация с условиями, при которых она меняется.
5. Красная команда: запусти субагента `red-team` с путями `options.md` и `evidence/claims.jsonl`. Внеси его
   возражения в карточки вариантов. Для второй точки зрения другой модели: `python sf.py llm critic --prompt-file options.md`.
6. Pre-mortem рекомендуемого варианта (5 причин провала) — в его «Риски».
7. `python sf.py check` → 0 ошибок. Покажи человеку: таблицу сравнения + рекомендацию + главный риск каждого
   варианта (не весь файл). `checkpoint --waiting --next "выбор варианта человеком (G2)"`.
8. Выбор человека → `python sf.py gate G2 pass --note "выбран вариант X: <причина>"` → `python sf.py stage strategy`.
