# Навык: пересмотр при новых данных

1. Зарегистрируй новое: `python sf.py fetch <url>` / `ingest <файл>` (или правка человека — утверждение с источником «со слов человека», `--kind opinion`/`fact` по смыслу).
2. Кандидаты: `python sf.py revisit <S…>` (лексическая близость + совпадение чисел; `--llm` — судья другого
   семейства оценит «подтверждает/противоречит/уточняет»).
3. Для каждого затронутого утверждения реши: подтверждено (добавь источник), уточнено (`claim update --text-new`),
   опровергнуто (`claim retract --reason ... --by <новое C…>`), спорно (`--status disputed`).
4. `python sf.py impact <C…> --mark-stale` по каждому изменённому — затронутые разделы и решения попадут в `state.yaml → stale`.
5. Обнови каждый затронутый раздел; в начале раздела — пометка «Обновлено <дата>: <что и почему>».
   Если меняется рекомендация — скажи об этом человеку явно (было → стало → почему) и предложи пересмотреть решение (G2/G3).
6. `python sf.py stale --file <файл>` после обновления; `python sf.py check` → 0 ошибок; `decisions due`.
7. Урок для будущих проектов — `python sf.py memory add --kind lesson --prov "<проект, источник>"`.
