# План проверки

## Обязательные элементы (проверяются `sf check`)
1. **Ожидаемое изменение** — метрика, направление и *минимальный значимый эффект* (MDE):
   «доля подключивших среди целевого сегмента вырастет с X до ≥Y за N недель».
2. **С чем сравниваем** — контрольная группа (A/B, holdout), регион-контроль (diff-in-diff),
   исторический базис (слабее: сезонность). Указать, почему сравнение честное.
3. **Срок наблюдения** — с обоснованием: длина цикла поведения, сезонность, размер выборки
   (n на группу ≈ 16·p(1−p)/MDE² для долей при α=0.05, мощности 80%).
4. **Нежелательные последствия (guardrails)** — что не должно ухудшиться: жалобы, отписки,
   отток основной услуги, нагрузка на поддержку, ложные срабатывания, доверие (упоминания).
5. **Критерии решения** — заранее: «масштабируем, если…», «останавливаем, если…», «продлеваем, если…».
6. **Ответственные и дата решения** — переносятся в `decisions.yaml`.

## Иерархия доказательности
рандомизированный эксперимент > квазиэксперимент (регион-контроль) > до/после > мнения/опросы.

## Ранние сигналы
Для долгих метрик (отток) — опережающие индикаторы: активация функции, повторное использование,
доля пользователей с включёнными уведомлениями.
