# 02. Ревью архитектуры: консультация с Claude Sonnet 5.5 (роль «член жюри»)

Дата: 2026-11-14 · Субагент: `general-purpose`, модель **sonnet**, режим только чтение · Токены: ~58,6 тыс. · Время: 33 с

**Запрос (кратко):** «Ты — строгий член жюри… Прочитай условие и проект архитектуры. Оцени по 4 критериям, назови топ-7 рисков, что добавить/убрать, оцени демо-тему, как доказать жюри».

## Ответ Sonnet (сжато, ключевое — дословно)

| Критерий | Оценка проекта «как есть» | Что мешает 10 |
|---|---|---|
| 1. Проработанность | 6/10 | «Вся архитектура описывает инфраструктуру, а не содержание стратегии»: нет шаблонов с обязательными полями, механики решающих вопросов, честных условий для «оставить/закрыть», плана проверки |
| 2. Нейротехнологии | 7/10 | компоненты «списком, а не обоснованы пользой»; нужен измеренный вклад |
| 3. Имплементация | 5/10 | объём нереалистичен → риск недоделанного сквозного пути; хуки не переносятся в другие IDE; нет режима без ключа и `doctor` |
| 4. Качество | 5/10 | нет одностраничного документа для руководителя, статуса стадии, пути «исправить»; неточный учёт стоимости IDE-модели |

**Топ-риски:** раздутый объём · ID моделей надо сверять с живым списком · политика отправки данных внешним моделям · детектор инъекций по паттернам обходится — нужна архитектурная изоляция · ротация моделей-респондентов создаёт иллюзию разнообразия · dev-режим для хука правил должен быть понятным · сравнение с чатом через ИИ-судей самоподтверждающееся — нужны ограничения и ручная выборка фактов.

**Как доказать жюри:** воспроизводимый журнал прогона · `sf check` красный → зелёный на пойманном дефекте · resume в новом чате · сценарий пересмотра с diff · таблица стоимости · ручная проверка 15–20 утверждений · тест инъекции · сравнение с чатом с честным n=1 · холодный старт с временем.

## Решения по итогам ревью (что изменено в архитектуре)

| # | Замечание | Решение | Где реализовано |
|---|---|---|---|
| 1 | Нет содержания стратегии | Шаблоны с обязательными разделами + `sf check` проверяет их заполненность, наличие вариантов «оставить» и «закрыть», плана проверки | `knowledge/templates/`, `strategist/evidence.py::check_structure` |
| 2 | Нет режима без ключа | Без `OPENROUTER_API_KEY` всё работает на IDE-модели и субагентах; плюс режим **replay** по сохранённым ответам моделей | `strategist/llm.py` (`NoKeyError`, `STRATEGIST_REPLAY`) |
| 3 | Раздутый объём | Ядро — 10 команд; остальное — расширения, каждое покрыто дымовым тестом | `scripts/smoke_test.py`, `tests/` |
| 4 | Инъекции | Изоляция: исследователь не имеет права записи и Bash, факт-чекер — только чтение; источники хранятся как данные в карантинной обёртке; детектор — второй рубеж | `.claude/agents/*.md`, `strategist/safety.py` |
| 5 | Ротация респондентов | По умолчанию одна модель; ротация — опция, без заявлений о «разнообразии» | `config/routing.yaml` |
| 6 | Dev-режим хука | Явное правило: правки правил разрешены, только если есть файл `.dev-mode` (в `.gitignore`), иначе хук спрашивает человека | `strategist/hooks.py` |
| 7 | Сравнение с чатом | n=1 и ограничения названы явно; судьи другого семейства (DeepSeek/Qwen), слепой порядок; выборочная проверка фактов | `evals/` |
| 8 | Документ для руководителя | Одностраничная сводка: решение, три риска, что проверить за 2 недели, стоимость прогона | `knowledge/templates/one-pager.md` |
| 9 | Переносимость гарантий | Таблица «что гарантируется в какой IDE»; git pre-commit хук на секреты не зависит от IDE; Cursor hooks для паритета | `docs/architecture.md` |
| 10 | Политика данных | Внешним моделям — только открытые данные; ПДн вычищаются до отправки; интервью без флагов согласия не отправляются | `strategist/safety.py`, `AGENTS.md` |
