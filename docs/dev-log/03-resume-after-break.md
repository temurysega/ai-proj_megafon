# 03. Продолжение после перерыва: новый чат, та же точка

Дата: 15.11.2026 · Сценарий проверки требования «работу можно остановить и продолжить с сохранённого места, в том числе открыв новый чат».

## Что произошло
1. 14.11.2026 агент довёл демо-проект до стадии «Варианты» и задал человеку вопрос ворот G2. Сессия оборвалась до ответа
   (вызов вопроса прерван — «the session ended before this call's result was recorded»).
2. 15.11.2026 открыт **новый чат** Claude Code. Пользователь написал одно слово: «продолжай».
3. Хук `SessionStart` (`scripts/hook.py session_start`) сам подал в контекст состояние из `projects/antifraud-family/state.yaml`
   и хвост журнала — до того, как агент что-либо прочитал:

```
[Стратег] Восстановлено состояние проекта из файлов (продолжение после перерыва).
Проект: antifraud-family — Семейная защита от телефонных мошенников: что делать с продуктом и как о нём говорить
Режим: checkpoints · Стадия: 3. Варианты и выбор (waiting_human)
Ворота: G1_brief=passed, G2_option=pending, G3_strategy=pending
Следующее действие: показать варианты человеку и получить выбор (ворота G2)
Доказательная база: источников 39, утверждений 67 (...)
Стоимость: внешние модели $0.0000 (0 вызовов), IDE-модель ≈$4.85 (оценка по токенам)
Последние действия: ... checkpoint: options.md v2 после красной команды и факт-чекинга ...
Сбоев в журнале: 3 (последний: check — ошибок 6, предупреждений 1)
```

4. Агент не переспрашивал бриф и не повторял исследование: он сразу повторил вопрос ворот G2 (единственное, что ждало человека).
   Человек выбрал «A+ и эксперимент» → `sf gate G2 pass` → `sf stage strategy`.
5. В этой же сессии MCP-сервер проекта `strategist` (из `.mcp.json`) подключился к Claude Code автоматически: агент вызвал
   `project_status` и `add_claim` как MCP-инструменты (утверждения C068, C069 добавлены через MCP).

## Что это доказывает
- Состояние задачи живёт в файлах, а не в памяти чата: новый чат продолжает с конкретного шага за 1 действие.
- Незавершённое действие (вопрос ворот) не потерялось: `state.yaml → stage_status: waiting_human` + `next_action`.
- Повторной оплаты нет: выполненные шаги (импорт исследователей, интервью) отмечены в журнале ключами идемпотентности.

## Переносимость в другую IDE
Тот же сценарий в Cursor/Copilot: правило `.cursor/rules/strategist.mdc` / `.github/copilot-instructions.md` велит первым
действием выполнить `python sf.py status` — вывод тот же, что подал хук (функция `status_text`).
