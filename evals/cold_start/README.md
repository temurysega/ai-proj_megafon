## Студия керамики

21 ноября 2026 года модель Codex в IDE получила новый продуктовый запрос в отдельном клоне коммита `954cddf`.
Кейс студии керамики и данные вымышлены. [Исходная сводка](studio-brief.md) доступна отдельно.

> Почему люди не приходят на занятия после брони и что сделать, не ухудшив доверие?

В режиме `autopilot` модель оформила подтверждения на трёх этапах как допущения. Она подготовила бриф, импортировала сводку, завела реестр утверждений и сравнила четыре решения, в том числе оставить текущий процесс и закрыть предварительное бронирование. В отчёт вошли продуктовая и коммуникационная стратегии, план проверки, резюме и журнал решения. Выбор обратимого напоминания опирался на существующую ссылку отмены. Причину неявок предложено проверять в пилоте.

## Повторить работу модели с нуля

Откройте чистый клон в IDE, отправьте цитированный запрос и приложите `evals/cold_start/studio-brief.md`. Укажите использовать только сводку и пройти этапы в `autopilot`, записав допущения. Для проверки остановки и продолжения можно на этапе вариантов написать «стоп», открыть новый чат и написать «продолжай». Оценочные формулировки могут меняться между запусками. Доли из сводки и ссылки на её строки можно проверить независимо.

По журналу сквозной прогон занял 2 мин 44 с от создания проекта до чекпойнта сопровождения. В нём один учебный источник, 0 вызовов платных API и условные решения в точках согласования. Расходы модели IDE и время реального руководителя не измерялись. Эти цифры относятся к кейсу студии керамики.

## Цифровой каталог библиотеки

В отдельном чистом клоне коммита `031c218` модель Codex в IDE получила запрос «Почему посетители цифрового каталога редко резервируют экземпляр и какую обратимую доработку проверить первой?» и [учебную сводку](library-brief.md). Она сравнила четыре варианта и предложила проверить показ актуального статуса наличия в выдаче. В сводке доля подтверждённых резервов различалась между сессиями, а причину разницы предстоит проверить в контролируемом пилоте.

Модель восстановила стадию вариантов, ожидавшую решения G2, отдельной командой по состоянию на диске. Подтверждения G1–G3 записаны как допущения в режиме `autopilot`. Между созданием проекта и чекпойнтом сопровождения прошло 3 мин 3 с по журналу. Вызовов платных API было 0. Стоимость модели IDE и время руководителя не измерялись.

Агент после чтения контекста источника сузил утверждение C002. Сводка указывает, что **только статус** доступен исключительно на странице экземпляра, и перечисляет, что ещё видно на этой странице. Строгая проверка распознала дословную цитату и в первой версии. Смысловую правку можно проследить в журнале.

Для воспроизведения в отдельном клоне выполните:

```text
python sf.py import evals/cold_start/library-finder-audit.zip
python sf.py -p library-finder-audit check --strict
python sf.py -p library-finder-audit decisions check
python sf.py -p library-finder-audit status --plain --brief
python sf.py -p library-finder-audit decisions due
```

[Архив прогона](library-finder-audit.zip) включает вход, обе стратегии, план пилота, отчёт, журнал действий и обязательство D1/K1 по сверке статусов. После импорта строгая проверка даёт 0 ошибок, 0 предупреждений и 3 дословные цитаты.
